# AGENTS.md

## Назначение

Этот проект является стартовым шаблоном для верстки на Vite + Pug + SCSS + JavaScript modules.

Агент обязан сохранять текущую архитектуру проекта и работать в рамках существующей структуры файлов.
Не заменять стек на HTML/CSS/React/Vue/TypeScript/Tailwind или другой подход без прямого запроса.

## Обязательные правила проекта

Перед любыми изменениями прочитай и соблюдай:

- `docs/ai/project-rules.md`
- `docs/ai/pug-rules.md`
- `docs/ai/scss-rules.md`
- `docs/ai/js-rules.md`

Масштаб десктопа (zoom 1280–1920, широкие экраны до 2560) — `.agents/rules/desktop-scale.mdc`. Применять при вёрстке десктопа, в SCSS, JS и PHP-шаблонах.

## Главный workflow агента

Перед созданием или изменением кода:

1. Изучи текущую структуру проекта.
2. Найди похожие существующие секции, миксины, SCSS-файлы и JS-модули.
3. Переиспользуй существующую верстку и логику, если это возможно.
4. Создавай новые файлы только когда это действительно нужно.
5. Используй Pug для разметки.
6. Используй SCSS для стилей.
7. Используй модульный JS.
8. Не дублируй верстку, стили и JS-логику.
9. После создания Pug-секции создай соответствующий SCSS-файл и подключи его в `src/styles/styles.scss`.
10. Проверь, что изображения находятся только в `src/assets/img`, а шрифты только в `src/assets/fonts`.
11. Повторяющийся контент вынеси в `src/data/*.json`, картинки выводи через `+picture`.
12. Перед сдачей запусти `npm run build` и `npm run visual -- --pages=<страница>`, просмотри снимки в `.tmp/visual/`.
13. Обнови готовность страницы: `//- @progress: …` в её мета (карта страниц — `.agents/rules/page-map.mdc`).

## Запрещено

- Создавать `.html` файлы для исходной разметки.
- Писать обычный CSS вместо SCSS.
- Использовать внешние шрифты через Google Fonts/CDN.
- Класть изображения или шрифты в `public/`.
- Дублировать Pug-разметку вместо использования `include` или `mixin`.
- Писать большие куски JS напрямую в `main.js`.
- Использовать нечитаемые селекторы вроде `.blk1`, `.item2`, `.h-t`.
- Хардкодить повторяющиеся цвета в компонентных SCSS-файлах.
- Писать медиазапросы напрямую без миксина.
- Подключать библиотеки в `main.js` или `styles.scss` — только в модуле блока.
- Писать пути `/src/assets/…` или `/assets/…` руками — только `asset()` / `+picture`.
- Менять архитектуру проекта без явного запроса.
