# Project Rules

## Стек проекта

- Vite
- Pug
- SCSS
- JavaScript modules

Агент должен сохранять этот стек и текущую архитектуру.

## Базовая структура

```txt
src/
  assets/
    fonts/              шрифты (woff2)
    img/                картинки; webp/avif-пары — npm run images
    video/              видео (папка создаётся при необходимости)
  components/
    sections/           секции, которые встречаются один раз
    mixins/             повторяющиеся блоки (подключаются автоматически)
  data/                 данные для Pug в JSON: data/site.json → data.site
  layouts/              общий каркас страницы
  pages/                страницы: один .pug — одна страница
  scripts/
    components/         модули блоков (грузятся лениво, см. js-rules)
    pages/              скрипты страниц: pages/<data-page>.js
    utils/              утилиты
    main.js             только точка входа
  styles/
    components/         один BEM-блок — один файл
    core.scss           variables + mixins одной строкой
    variables.scss      значения: макет, масштаб, брейкпоинты, сетка, цвета
    mixins.scss         медиазапросы, контейнер, масштаб, шрифты, служебное
    base.scss           токены :root, body, .page, .page-scale
    fonts.scss          @font-face через миксин fontFace
    reset.scss
    styles.scss         точка подключения
scripts/                images.mjs, visual.mjs
public/
  robots.txt
```

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | сервер разработки, `index.html` — карта всех страниц |
| `npm run build` | сборка в `build/` |
| `npm run build:cms` | сборка для CMS: без хешей, пути относительные, без HTML. Папка — `CMS_OUT_DIR` в `.env.cms.local` |
| `npm run images` | webp рядом с каждым jpg/png (`-- --avif` — ещё avif) |
| `npm run visual` | снимки страниц на 390–2560 и проверки масштаба, см. ниже |

## Страницы

Каждая страница начинается с мета-комментариев:

```pug
//- @title: Контакты
//- @description: Адрес, телефоны и схема проезда.
//- @page: contacts
//- @page_class: contacts
extends ../layouts/default.pug
```

- `@title`, `@description` — заголовок и описание страницы;
- `@page` — имя для `body[data-page]` и `scripts/pages/<имя>.js` (по умолчанию — имя файла);
- `@page_class` — модификаторы `page--…` и `main--…`;
- `@has_intro` — есть ли у страницы первый экран, поверх которого лежит прозрачная шапка (по умолчанию `true`; страницам без интро — `false`), см. «Шапка и первый экран»;
- `@robots`, `@canonical` — при необходимости.

Новая страница сама появляется на карте страниц (`index.html`).

## Шапка и первый экран

Шапка фиксированная (`position: fixed`), высота — `--header-h` (`$header-h`, `$header-h-md` в `variables.scss`). Поведение зависит от `@has_intro` страницы → `html[data-has-intro]`:

| `@has_intro` | Шапка | Контент |
|---|---|---|
| `true` (по умолчанию) | прозрачная, цвет текста `$color-on-intro`, пока под ней первый экран; после него — сплошная, класс `is-solid` | интро начинается от верха окна, свой контент сдвигает вниз на `var(--header-h)` |
| `false` | сразу сплошная | `main` получает `padding-top: var(--header-h)` |

- Интро — секция с атрибутом `data-intro`; если его нет, первая секция в `main`.
- Класс `is-solid` ставит `scripts/components/initHeader.js`. Без JS шапка сплошная.
- Стили обоих состояний — в `header.scss`: прозрачное — селектор `.is-js[data-has-intro='true'] .header:not(.is-solid)`, сплошное — `.header.is-solid` и обычные стили `.header`.
- Высота интро «на весь экран» внутри масштаба — `calc(100svh / var(--page-zoom))`, не `100vh` (см. desktop-scale.mdc).

## Данные

Повторяющийся контент (карточки, цены, контакты, пункты меню) — в `src/data/*.json`, не в разметке. Файл `src/data/offices.json` доступен в Pug как `data.offices`, `site-menu.json` — как `data.siteMenu`. Правка JSON перезагружает страницу.

Структуру JSON делать такой, какой будут данные в CMS (поля записи инфоблока или поста): при переносе меняется только источник данных.

## Assets

- Изображения — только `src/assets/img/`, шрифты — только `src/assets/fonts/`.
- В Pug путь к файлу — только через `asset()`: `asset('img/hero/bg.jpg')`. Он работает и в разработке, и после сборки. Пути `/src/assets/…` и `/assets/…` руками не писать.
- Фото в разметке — миксин `+picture` (webp/avif, размеры, ленивая загрузка), см. `pug-rules.md`.
- После добавления фото — `npm run images`, webp/avif-пары коммитятся вместе с исходником.
- В `public/` — только `robots.txt`.

## Fonts

Все шрифты локальные, только woff2, подключение — в `src/styles/fonts.scss` через `@include fontFace(...)`. Основной шрифт предзагружается: часть имени файла — в `PRELOAD_FONTS` (`vite.config.mjs`).

Запрещено использовать Google Fonts, Adobe Fonts, CDN и внешние URL для шрифтов, если пользователь явно не попросил обратное.

## Десктоп: масштаб макета

Десктоп верстается в пикселях макета и масштабируется целиком через `zoom` (правило `.agents/rules/desktop-scale.mdc`). Ширина макета и границы масштаба — в `variables.scss` (`$design-desktop`, `$scale-from`, `$scale-to`), выключить — `$use-desktop-scale: false`. Ниже `$scale-from` — обычный адаптив.

## Создание новой секции

1. Pug-файл в `src/components/sections/` (или миксин в `src/components/mixins/`, если блок повторяется).
2. SCSS-файл с таким же именем в `src/styles/components/`, первая строка — `@use '../core' as *;`.
3. Подключение SCSS в `src/styles/styles.scss`: `@use 'components/<имя>';`.
4. Секция подключается на странице через `include` или вызов миксина.

## Переиспользуемые блоки

Если блок повторяется на других страницах с другим контентом — фото, текстом, ссылками, карточками — он оформляется Pug-миксином в `src/components/mixins/`. Миксины подключаются автоматически: достаточно создать файл, вызывать — `+имяМиксина({...})`.

Каждый переиспользуемый блок:

- отдельный Pug mixin;
- отдельный SCSS-файл с одним корневым BEM-классом;
- отдельный JS-модуль, если у блока есть поведение;
- человекочитаемое название.

Миксин = будущий шаблон компонента CMS. Где в разметку выводятся данные, ставить комментарий `//- CMS: <поле>` — при переносе видно, что откуда берётся.

## Запрет на дублирование

Не дублировать вёрстку, стили и JS-логику. Повторяющаяся разметка — миксин, повторяющаяся логика — `src/scripts/utils/` или `src/scripts/components/`.

## Обязательная проверка перед завершением

1. Файлы созданы в правильных папках.
2. Pug-разметка не дублируется, секции подключены через `include` или миксин.
3. Для новых секций и блоков есть SCSS-файлы, они подключены в `styles.scss`.
4. Цвета, брейкпоинты, размеры — из переменных; медиазапросы — через миксины.
5. Повторяющийся контент — в `src/data/*.json`.
6. Картинки — через `+picture` / `asset()`, есть webp-пары (`npm run images`).
7. JS разделён на модули, библиотеки подключены только в модулях блоков.
8. `npm run build` проходит без ошибок.
9. `npm run visual -- --pages=<страница>` — без замечаний; снимки в `.tmp/visual/` просмотрены.
10. `public/` не содержит ничего кроме `robots.txt`.
